# Phase 55 — Trier les cartes par code postal

**Branche :** `{{BRANCH}}` · **Migration réservée :** `0022_postal_code` · **Base :** `{{PARENT}}`

## Objectif

Traiter **I-002** de `.docs/09-idees.md`. Les listes de cartes se trient par rareté, par score ou
par date ; le tri naturel de « ma collection autour de chez moi » manque. `ref_communes` ne porte
**aucune** colonne de code postal : ce n'est pas une option d'affichage, c'est une évolution du
contrat de données.

Cette phase ajoute `ref_communes.code_postal`, l'alimente à l'import depuis le champ
`codesPostaux` de `geo.api.gouv.fr`, l'expose dans `GET /api/v1/cards`, et ajoute une colonne
« Code postal » triable au Cadastre.

## Décisions déjà prises — ne les rediscute pas

1. **La base est `{{PARENT}}`.** PR **brouillon vers `{{PARENT}}`**, jamais `main`.
2. **Un seul code postal par commune : le « principal ».** `geo.api.gouv.fr` publie
   `codesPostaux` en tableau et n'en désigne aucun ; la règle est **le premier code à cinq
   chiffres non vide** de ce tableau. Elle vit dans `packages/shared/src/postal.ts`
   (`principalPostalCode(codesPostaux)`, plus `POSTAL_CODE_PATTERN = /^\d{5}$/`) et elle est
   verrouillée par la spec. Le tableau complet n'est **pas** stocké dans cette phase.
3. **Une seule migration : `0022_postal_code`.** `add column if not exists code_postal text` en
   SQL brut (Kysely n'expose pas `ifNotExists`), et
   `create index if not exists ref_communes_code_postal_idx on ref_communes (code_postal)`.
   Rejouable : ni `NOT NULL`, ni défaut.
4. **La colonne est nullable dans le type Kysely**, et `Generated<string | null>` : elle n'a pas
   de défaut SQL, mais omission = `NULL` (colonne nullable), et des fixtures de spec insèrent des
   communes sans code postal. Le type doit le permettre sans réécrire ces fixtures.
5. **`.docs/02-database.md` est mis à jour par cette phase** — c'est l'exception explicite au
   préambule : §2 (ligne de migration `0022_postal_code`), §5 (le DDL), §6 (`RefCommuneTable`).
   Aucun autre document n'est touché.
6. **`GET /cards` porte `codePostal`** pour les communes, `null` pour les trois autres catégories
   (une région, un département ou une rue n'a pas de code postal de carte). Aucun autre champ
   nouveau.
7. **Le tri est local au tableau**, pas dans l'URL : la colonne « Code postal » est triable comme
   les autres (`sortFn` texte/alphanumérique), et le tri par défaut reste `acquired_at desc`.
   Le filtre « par tranche » est **différé** et écrit dans la revue : il demande une décision
   produit sur les tranches (département ? région ? 01–95 ?) qu'aucune entrée de `.docs` ne
   tranche.
8. **Une commune sans code postal affiche « — »**, jamais une case vide ni un tri instable.
