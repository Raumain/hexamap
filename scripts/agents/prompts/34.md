# Phase 34 — L'Assemblage, l'API

**Branche :** `{{BRANCH}}` · **Migration réservée :** aucune · **Base :** `{{PARENT}}`

## Objectif

Servir à la salle exactement ce qu'elle doit dessiner, en **une requête par niveau**. Le serveur
reste la seule autorité : il compte les communes couvertes, il dit quelle entité est possédée, il
ne transmet jamais `locked`, ni la grille d'un ticket, ni un solde.

Deux routes, et rien d'autre. Elles ne sont pas un début de client de carte : la phase 35 consomme
ce contrat tel quel, sans le compléter.

## Décisions déjà prises — ne les rediscute pas

1. **La base est `feat/v2-wave-2`.** `main` est en lecture seule. La PR est un **brouillon vers la
   branche parente de la vague**, jamais vers `main`.
2. **`ownedCards` est un nombre, pas une liste.** Il compte les **exemplaires** : trois cartes de la
   même commune donnent `ownedCards: 3`. Aucune liste d'identifiants de cartes ne sort de cette API
   — la salle n'en a pas besoin, et une liste est une fuite de données privées par construction.
3. **Les compteurs agrégés comptent `distinct` sur `ref_code`.** `communesOwned` et
   `communesTotal` d'une région ou d'un département ne comptent jamais deux fois une commune
   possédée en double. C'est le seul endroit où la règle s'inverse, et elle s'inverse explicitement.
4. **`pathD` est la chaîne brute, déjà exprimée dans le `viewBox` partagé.** Le serveur ne
   reprojette rien, ne simplifie rien, n'arrondit rien. Le type est `string | null` : `null`
   signifie **hors carte** (outre-mer, décision de la phase 33), jamais « pas encore chargé ».
5. **Le `viewBox` est renvoyé par les deux routes**, lu depuis `packages/shared/src/atlas.ts`
   (à créer) qui exporte `ATLAS_VIEWBOX = '0 0 1000 1000'`. Une seule source, partagée avec la
   salle : le serveur ne la recalcule pas, la salle ne la déclare pas.
6. **Pas de pagination.** La phase 33 tient la charge nationale sous 250 Ko, donc un département est
   sous ce plafond par construction. Le plafond par département est fixé à **60 Ko** non compressés,
   mesuré en intégration. S'il est dépassé, la correction est un epsilon plus grand **à l'import** :
   tu l'écris dans le journal et tu ne pagines pas.
7. **Aucune rue.** Une carte `RUE` n'entre dans aucun compteur ni dans aucune réponse de ces deux
   routes. Le référentiel des odonymes n'est jamais joint.
8. **Codes d'erreur.** Pas de session : `401` par le groupe existant. Code inconnu, ou code
   d'outre-mer : `404 DEPARTEMENT_NOT_FOUND`, message français. Aucun `403` ici : il n'existe pas
   d'entité privée sur une carte publique.
9. **Aucune migration.** Le schéma ne bouge pas : la phase 33 a livré `path_d`, cette phase la lit.

## Ce que tu produis

1. **`packages/shared/src/atlas.ts`** (à créer) : `ATLAS_VIEWBOX`, et le type des deux charges
   utiles. Module pur, sans dépendance, sans `process.env` — la salle et l'API importent le même
   fichier.
2. **`apps/api/src/routes/atlas.ts`** (à créer), monté sur le groupe authentifié sous `/api/v1`,
   avec les schémas `response` TypeBox **complets** — chaque champ déclaré, aucun `t.Any()`, aucun
   objet ouvert — pour que Eden Treaty type la salle sans `as`.
3. **`GET /api/v1/atlas/summary`** :

   ```text
   { viewBox,
     regions:      [ { code, nom, pathD, hasRegionCard, communesOwned, communesTotal } ],
     departements: [ { code, nom, codeRegion, pathD, hasDepartementCard,
                       communesOwned, communesTotal } ] }
   ```

   Les deux listes sont plates et complètes. Aucune imbrication département-dans-région : la salle
   n'en a pas besoin et l'aplatissement rend la sérialisation mesurable.
4. **`GET /api/v1/atlas/departements/:code`** :

   ```text
   { viewBox, code, nom, communesOwned, communesTotal,
     communes: [ { codeInsee, nom, pathD, ownedCards, hasCommuneCard } ] }
   ```

5. **`apps/api/src/services/atlas.ts`** (à créer) : la couche requête. **Une instruction SQL par
   route**, un agrégat par entité, aucun `select *`. La possession se résout par
   `user_cards(user_id = $1, category = …)` agrégée, jamais par un aller-retour par ligne. Si tu
   écris une boucle sur les entités, la phase est fausse.
6. **`packages/spec/src/atlas.spec.ts`** (à créer) : les cas de contrat — `401` sans session, `404`
   sur code inconnu, `ownedCards` = exemplaires, `communesOwned` = distinct, `null` d'outre-mer,
   absence de `locked`, absence de rue.

## Critères d'acceptation

1. **Une seule requête agrégée par route**, prouvée par le journal SQL de l'essai d'intégration :
   aucune boucle N+1, aucun aller-retour par entité.
2. Réponse **sous 200 ms** pour un compte de **2 000 cartes**, mesurée en intégration sur
   PostgreSQL réel. Décris la mesure : vingt appels, p95 cité, base semée par le test lui-même.
3. Les schémas `response` sont complets : un champ ajouté au service sans schéma fait échouer le
   typecheck, et Eden type la salle sans cast.
4. `401` sans session ; `404 DEPARTEMENT_NOT_FOUND` sur un code inconnu et sur un code d'outre-mer ;
   `200` sur un département valide, y compris sans aucune carte possédée.
5. Aucune donnée privée dans les deux charges utiles — ni solde, ni session, ni `locked`, ni rue.
6. La charge d'un département dense reste sous **60 Ko** non compressés, chiffre cité.
7. `ci:check` vert à chaque commit, base de test `{{TEST_DB_URL}}`.
