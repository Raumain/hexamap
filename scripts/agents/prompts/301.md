2. Index exact :

```sql
create unique index if not exists currency_ledger_purchase_uniq
  on currency_ledger (user_id, reason)
  where reason like 'PURCHASE:%';
```

4. Semis idempotent :

```sql
insert into game_config (key, value)
```

6. `down` : `drop index if exists` et `delete from game_config where key = ...`. Les migrations
   livrées ne changent plus de nom, mais leur `up` reste rejouable.

## Pièges

- Ne modifie **aucune** migration existante : `0001` à `0012` sont livrées.
- `on conflict do nothing` sans cible est le plus sûr : il attrape l'index partiel sans avoir à
  répéter son prédicat.
- Ne supprime pas `kysely_migration` dans la spec : la procédure de rejeu se fait à la main sur
  une base de test jetable, pas dans une suite qui tourne en CI.
- Le `CHECK` de `user_scratch_charges` n'a aucune borne haute ; ne réintroduis pas cette erreur
  pour `SHOP_DAILY_PURCHASE_CAP` : c'est une clé `game_config`, pas une contrainte.
- Le motif est `'PURCHASE:%'`, pas `'PURCHASE_REFUND:%'` : un remboursement n'est pas une
  purchase et ne doit pas être bloqué par cet index.

## Critères d'acceptation

1. L'index partiel existe après migration.
2. Deux `PURCHASE:<même id>` avec `on conflict do nothing` → une ligne.
3. Deux `MARKET_BUY` identiques → deux lignes.
4. `SHOP_DAILY_PURCHASE_CAP` vaut `12000`.
5. La migration se rejoue sans erreur (`if not exists`, `on conflict do nothing`).
6. `ci:check` vert.
