# Phase 30.4 — La salle de la Boutique et la page de succès

**Branche :** `{{BRANCH}}` · **Migration réservée :** `{{MIGRATION}}` · **Base :** `{{PARENT}}`

## Objectif

Ouvrir `La Boutique` : quatre packs, prix TTC, solde d'écus, un bouton qui redirige vers
Stripe Checkout, et une page de succès qui **lit le webhook** au lieu de croire la redirection.
Sans clés Stripe, la salle affiche un message propre et ne propose pas d'achat.

Cette phase suppose la vague 2 fusionnée : `POST /shop/checkout`, `GET /shop/orders/:id` et les
types Eden existent.

## Décisions déjà prises

1. **Route** : `apps/web/src/routes/boutique.tsx` pour la salle, `boutique.succes.tsx` pour
   `/boutique/succes`. Ne jamais éditer `routeTree.gen.ts` à la main : `tsr generate` le produit.
2. **Navigation secondaire** : ajouter `La Boutique` à `SECONDARY_NAV`, `SALON_TITLES` et
   `isSecondaryRoom`. Elle est atteinte en deux appuis depuis `/` sur téléphone via la feuille
   `Plus`. Pas de sixième onglet principal : la barre basse reste à quatre salles.
3. **Contenu** : `apps/web/src/content/boutique.ts` porte tous les libellés français, les noms
   des packs, les mentions « prix TTC », et les messages `SHOP_DISABLED` /
   `SHOP_DAILY_CAP_REACHED`. Aucun texte dans le JSX.
4. **Prix** : `Intl.NumberFormat('fr-FR', { style: 'currency', currency: 'EUR' })` sur
   `priceCents / 100`. Le prix affiché est le prix payé ; aucune taxe ajoutée.
5. **Checkout** : le client n'envoie que `{ packKey }`. La réponse `{ url }` est suivie par
   `window.location.assign(url)`. Aucun montant, aucun nombre d'écus envoyé.
6. **Succès** : `/boutique/succes?session_id=...` lit `GET /shop/orders/:id` avec TanStack Query.
   - `PENDING` : « Paiement en cours de confirmation… », `refetchInterval` 2 s, plafonné à
     ~10 s, puis un bouton **Rafraîchir** et un message qui ne bloque pas.
   - `CREDITED` : affiche le nombre d'écus et le nouveau solde ; arrête le polling.
   - Jamais de crédit optimiste côté client.
7. **États d'erreur** : `503 SHOP_DISABLED` → « La boutique n'est pas encore ouverte. » ;
   `429 SHOP_DAILY_CAP_REACHED` → message français ; `UNKNOWN_PACK` → message générique.
8. **Aucune dépendance nouvelle, aucun i18n, aucun `useEffect` pour fetcher.** Le solde se lit
   depuis la session existante ; invalider la session après un ordre crédité.
9. **Aucun motif sombre** : pas de « cadeau », pas de compte à rebours, pas de fausse rareté,
   pas de prix barré. Quatre cartes, un bouton par carte.

## Pièges

- Ne crois jamais `?session_id` comme preuve de paiement : la page lit `/shop/orders/:id`.
- Le webhook peut arriver **après** la redirection : prévois `PENDING` et le polling court.
- Ne mets pas `refetchInterval` infini : plafonne et laisse un bouton manuel.
- Ne crée pas de sixième onglet : la feuille `Plus` est le chemin mobile prévu.
- Ne touche pas aux jetons de `styles.css` : les packs se dessinent avec l'existant.
- Ne rends pas un prix en euros flottant : `priceCents / 100` puis `Intl.NumberFormat`.
- Ne fetch pas dans un `useEffect` : TanStack Query uniquement.

## Critères d'acceptation

1. `/boutique` est atteignable en deux appuis depuis `/` sur téléphone.
2. Quatre packs, prix TTC français, bonus, solde.
3. Le checkout envoie seulement `packKey` et redirige vers `url`.
4. La page de succès affiche `PENDING` puis `CREDITED` en lisant l'API.
5. `503` et `429` ont un message français, sans bouton mort.
6. Aucun débordement à 390 px ; cibles ≥ 44 px.
7. Aucune dépendance nouvelle, aucun i18n, aucun `useEffect` de fetch.
8. `ci:check` vert et cas e2e mobile vert.
